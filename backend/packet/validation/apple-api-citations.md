# Apple API citations: iPhone capture-data spec

Sources: Apple DocC JSON (`https://developer.apple.com/tutorials/data/documentation/<path>.json`), fetched 2026-09-26. The docs now cover iOS 27. Every HTML URL below is the canonical `https://developer.apple.com/documentation/<path>` form; I spot-checked a sample and all returned HTTP 200. "Min iOS" comes from the page's `platforms` metadata. Quotes are verbatim unless marked "≈" (close paraphrase). Status: **V** = page content read; **U** = page not loadable, or the claim isn't on any Apple doc page.

## Surprises / caveats

- **`ARFrame.exifData` requires iOS 16.** `captureHighResolutionFrame` and the recommended high-res/4K video formats are also iOS 16. `captureHighResolutionFrame(using:)` with custom photo settings is iOS 26.
- **`ARFrame.timestamp` has no documented clock.** Core Motion is documented as "time in seconds since the device booted". `ProcessInfo.systemUptime` is documented as time "awake since … restarted". Apple never says these three are the same timebase, so don't assume they are without checking on a device. `systemUptime` also needs a privacy-manifest reason.
- **`CLLocation.timestamp` and `CLHeading.timestamp` are `Date` (wall clock), not uptime.** Aligning them with ARKit or Core Motion needs an explicit offset.
- **The 256×192 depth resolution isn't documented anywhere in ARKit.** Apple says only "low-resolution" and "smaller … same aspect ratio" (WWDC20, 60 Hz). `depthMap` pixel format is only an example (`DepthFloat32`), so query `CVPixelBufferGetPixelFormatType` at runtime.
- **`ARConfidenceLevel` and `ARMeshClassification` numeric raw values aren't in the docs**, except mesh `none` = 0. The 0/1/2 and 1–7 values come from third-party header mirrors.
- **The `ARCamera.transform` text uses `UIDeviceOrientation.landscapeLeft`, not "landscapeRight".** Device landscapeLeft means the Home button is on the right, which matches `AVCaptureVideoOrientation.landscapeRight` in the `.camera` alignment text. Specs that say "landscapeRight" must say which enum they mean.
- **`gravityAndHeading` is +x east, +y up, +z south** (−z = true north). That is *not* ENU and differs from Core Motion's `xTrueNorthZVertical` (X north, Z up). So ARKit world and CMAttitude frames need an explicit axis remap.
- **`intrinsics` is never called "column-major" in Apple's text.** Only the K figure and simd storage imply `columns.2 = (ox, oy, 1)`. Units are pixels relative to `imageResolution` (landscape sensor orientation).
- **ARKit exposes no lens-distortion data for the rear camera.** `AVCameraCalibrationData` is reachable only through `capturedDepthData`, which is front TrueDepth and face tracking only.
- **`displayTransform(for:viewportSize:)` has no Swift doc page any more.** The ObjC form is deprecated in iOS 27 in favour of `displayTransform(viewRotationAngle:viewportSize:)`. Similarly, `CLLocationManager.headingOrientation` is deprecated in iOS 27 with no documented replacement.
- **Core Motion units are split across pages.** `rotationRate` units (rad/s) and the device-axis definition appear only in articles, and the axes only in an illustration. The EXIF key pages give no units or value types at all, so rely on the EXIF spec.
- **No documented hard maximum for `deviceMotionUpdateInterval`** beyond "usually at least 100 Hz".
- **There is no Apple API documented to return a hardware identifier like "iPhone15,4".** `UIDevice.model` returns just "iPhone"; `utsname.machine` is documented only on an archived man page; `sysctlbyname`'s page lists macOS only.
- **Some Apple pages contradict each other or are stale.** `ARPlaneAnchor.classification` says "only on iPhone XS, iPhone XS Max, and iPhone XR", while `isClassificationSupported` says "A12 or later". `CLAccuracyAuthorization`'s enum page shows iOS 2.0+, but the property is iOS 14. `configurableCaptureDeviceForPrimaryCamera` says it is `nil` on devices without an ultra-wide camera.
- **`CMAbsoluteAltitudeData` requires iOS 15 and "iPhone 12 and later"**, and `CMAltimeter` crashes without `NSMotionUsageDescription`.
